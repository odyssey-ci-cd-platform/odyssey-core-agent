## Summary

Process and documentation are unusually mature for the project's size, and the event-bus layer is solid.
The execution engine, however, violates three of its own written design principles: independent teardown context, stdout/stderr kept separate, and Failed distinct from Errored.
The tests lock the wrong behavior in rather than catching it.
The agent rulebook (`AGENTS.md`, `.agents/`) is gitignored, so the workflow it enforces exists only on one machine.

## New findings

### AUD-001 — Containers leak when a run is cancelled or times out

- **Severity:** Critical
- **Category:** correctness
- **Verification:** Confirmed
- **Location:** `internal/runner/docker.go:71`
- **Problem:** The deferred `removeContainer(ctx, …)` uses the run's context, which README and AGENTS.md explicitly forbid; teardown must use `context.WithoutCancel` plus its own timeout.
- **Failure scenario:** A job with step `sleep 30` run under a 4s context: `Run` returns, the remove call fails on the cancelled context, and the `tail -f /dev/null` container keeps running indefinitely. Every gRPC client `-timeout` triggers this. An unrelated alpine container (`a0142a42307d`, up about 3 hours) was present on the auditor's host, consistent with an earlier leak.
- **Suggested fix:** Teardown under `context.WithTimeout(context.WithoutCancel(ctx), …)`; add a test that cancels mid-step and asserts no container remains.

### AUD-002 — `CreateTar` returns a truncated archive

- **Severity:** Critical
- **Category:** correctness
- **Verification:** Confirmed
- **Location:** `internal/common/utils.go:27`, `internal/common/utils.go:73`
- **Problem:** `buffer.Bytes()` is evaluated before the deferred `tw.Close()` runs, so the last entry's padding and the end-of-archive marker are missing; the `Close` error is also discarded.
- **Failure scenario:** A directory holding one 1-byte file yields a 1025-byte archive (not a multiple of 512). Docker tolerates it today; stricter consumers will not.
- **Suggested fix:** Close the writer explicitly, check its error, then return the bytes; assert archive validity (length and trailer) in tests.

### AUD-003 — Non-zero exit treated as an infrastructure error; real exit code discarded

- **Severity:** Critical
- **Category:** correctness
- **Verification:** Confirmed (by test assertion and code reading)
- **Location:** `internal/runner/docker.go:347-348`, `internal/runner/docker.go:254-256`, `internal/orchestrator/orchestrator.go:120`
- **Problem:** `execCommand` maps every non-zero exit to `ExitFailure` (1) and returns an `error`, so codes such as 2, 127, or 137 are lost. Step failures then travel the run-error path. Conversely, genuine infrastructure errors during steps (exec or inspect failures) yield `StatusFailed`, never `StatusErrored`, and the orchestrator logs the error without its value and drops it. The README's Errored-versus-Failed distinction holds only for setup.
- **Failure scenario:** A test suite exiting 2 and a Docker API failure mid-step both surface as `STATUS_FAILED`, exit code 1.
- **Suggested fix:** Return the real exit code with a nil error for non-zero exits; reserve `error` for infrastructure faults and carry them into the result so status becomes Errored.

### AUD-004 — gRPC result conflates stdout and stderr and omits facts the product needs

- **Severity:** High
- **Category:** architecture
- **Verification:** Confirmed (by code reading of the contract)
- **Location:** `api/v1/odyssey.proto:45`, `internal/server/mapping.go:33-37`, `internal/runner/docker.go:191-192`
- **Problem:** Stdout and stderr are merged into one `output` field, contradicting the stated principle at the API boundary. There is no setup error, duration, or timestamp in the contract. On internal errors the runner writes the error text into both Stdout and Stderr, fabricating process output.
- **Failure scenario:** An errored job returns no reason to the caller; trend analytics has no duration to consume.
- **Suggested fix:** Separate `stdout`/`stderr` fields, an error field per job and step, durations and timestamps.

### AUD-005 — Unauthenticated server reads arbitrary host paths

- **Severity:** High
- **Category:** security
- **Verification:** Plausible
- **Location:** `cmd/server/main.go:28-31`, `internal/server/server.go:47`
- **Problem:** The server binds all interfaces without TLS or authentication, and `project_path` is accepted verbatim, then tarred into a container. `ODYSSEY_ADDR` is really a port with `:` prepended, so binding to localhost is impossible.
- **Failure scenario:** Any host that can reach port 50051 runs a pipeline with `project_path=/home/<user>` and a step that prints files.
- **Suggested fix:** Bind localhost by default, accept a full address, and confine `project_path` to a configured root.

### AUD-006 — Unknown TOML keys are silently ignored

- **Severity:** High
- **Category:** correctness
- **Verification:** Confirmed (by code and fixtures)
- **Location:** `internal/common/utils.go:16`, `examples/pipeline.toml` (job field docs), `internal/config/models.go:16-22`
- **Problem:** `ReadToml` discards `MetaData.Undecoded()`, contradicting "reject contradictory combinations at parse time". Every job fixture sets `name`, and the example documents `name` as required, but `JobConfig` has no such field.
- **Failure scenario:** `timout = 500` (typo) is accepted and the step runs with no timeout.
- **Suggested fix:** Reject undecoded keys; remove or implement `name`.

### AUD-007 — A declared stage with no jobs leaves the pipeline Pending forever

- **Severity:** High
- **Category:** correctness
- **Verification:** Plausible
- **Location:** `internal/config/models.go:42-85`, `internal/domain/result.go:69-78`
- **Problem:** Validation allows a stage with no jobs; its result has no jobs and therefore status Pending, which dominates Passed.
- **Failure scenario:** `stages = ["build", "test"]` with jobs only in `build` finishes with `STATUS_PENDING`.

### AUD-011 — Step timeout: undocumented unit, mislabelled cancellation, redundant concurrency

- **Severity:** Medium
- **Category:** correctness
- **Verification:** Confirmed
- **Location:** `internal/runner/docker.go:212-258`, `internal/config/models.go:12`
- **Problem:** `timeout` is milliseconds, documented nowhere, and negative values are accepted. Parent-context cancellation is reported as "timed out after 0ms" (observed). The goroutine, channel, and select duplicate what `execCommand` already does by honoring its context.
- **Suggested fix:** Document or type the unit, validate it, distinguish timeout from cancellation, and simplify to a direct call.

### AUD-012 — Lifecycle events lost on cancellation; no run identifier

- **Severity:** Medium
- **Category:** architecture
- **Verification:** Plausible
- **Location:** `internal/orchestrator/orchestrator.go:112`, `internal/domain/event.go:18-25`
- **Problem:** Finished events are published on the job context, so they fail precisely when a run is cancelled. Events carry no run ID, so concurrent runs of the same pipeline are indistinguishable to consumers.
- **Suggested fix:** Publish finished events on an independent context; add a run ID to the envelope.

### AUD-013 — Consumer hot-loops while Redis is unavailable

- **Severity:** Medium
- **Category:** correctness
- **Verification:** Plausible
- **Location:** `internal/consumer/consumer.go:119-125`, `internal/consumer/consumer.go:146-175`, `internal/consumer/consumer.go:215`
- **Problem:** Read errors log and retry immediately with no backoff. Every loop iteration runs XPENDING plus one XAUTOCLAIM per pending entry, inspects only the first 64 pending entries, and malformed envelopes wait about 5×MinIdle before dead-lettering although they can never succeed.
- **Suggested fix:** Back off on errors, use a single cursor-driven XAUTOCLAIM pass, dead-letter unparseable entries immediately.

### AUD-014 — Docker client created per request and never closed

- **Severity:** Medium
- **Category:** correctness
- **Verification:** Plausible
- **Location:** `internal/server/server.go:55`
- **Problem:** Each `RunPipeline` call constructs a `DockerRunner` whose client is never closed, leaking connections and descriptors on a long-running server.
- **Suggested fix:** Create the runner once at server start and close it on shutdown.

### AUD-015 — Later stages run after earlier stages fail, as an unrecorded decision

- **Severity:** Medium
- **Category:** architecture
- **Verification:** Confirmed (by doc comment and code)
- **Location:** `internal/orchestrator/orchestrator.go:73-90`

### AUD-017 — Tests lock in defects and miss key behaviors

- **Severity:** Medium
- **Category:** testing
- **Verification:** Confirmed
- **Location:** `internal/runner/docker_test.go` (`TestDockerRunnerRunFailingCommand`, `requireDocker`), `internal/runner/envfile_test.go:1`, `internal/server/server_test.go:1`
- **Problem:** `exit 42` is asserted to produce `ExitFailure` and a run error, cementing AUD-003. ### AUD-020 — Workflow automation and templates have gaps
